# Service Worker Audit — 2026-06-26

Scope: `/sw.js` end-to-end + cache-bust cross-check on `games/g14.html`, `g15-pixi.html`, `g16-pixi.html`, `g14-side.html`. Read-only.

Context: v55.0 slim-SHELL ship landed after 12 `CACHE_VERSION` bumps chasing a "Memuat Pokedex…" eternal-spinner regression. Goal here: verify no other SW pathology remains.

## Verdict

SW lifecycle logic is correct. SHELL slim-down was the right call. One real P0 (network-first HTML has no timeout), one real P1 (un-versioned `trains-db.js` in g15-pixi.html), plus version-string drift between sibling pages.

## P0 — Could prevent SW from serving correctly

### P0-1. Network-first HTML has no timeout (sw.js:94-103)
On a slow/captive network, `fetch(req)` for the navigation request never resolves and never falls back to `caches.match`. The page just spins. This is the most likely remaining cause of "stuck loading" symptoms after the SHELL slim. Recommend a 3-5 s race against `caches.match`, then prefer fresh on win, cache on loss.

### P0-2. install-time `.catch(() => {})` swallows SHELL precache failures (sw.js:54)
`cache.addAll([...]).catch(() => {})` is atomic — one bad URL rejects the whole batch silently, install reports success, `skipWaiting()` fires, activate runs with an empty asset cache. Effect: deployment is non-fatal but offline-first is silently broken. Recommend logging via `console.warn` and/or per-URL `Promise.allSettled(cache.add(u))` so a single 404 doesn't void the entire shell.

### P0-3. SHELL paths are GitHub-Pages-shaped only
SHELL uses `/Dunia-Emosi/...` absolute paths (matches `manifest.json` scope). If the same SW is ever served from `dunia-emosi.vercel.app` (root), every SHELL entry 404s and P0-2 hides it. Not a regression today, but a foot-gun. Use relative URLs or branch on `self.location.pathname`.

## P1 — Stale-asset risks

### P1-1. `g15-pixi.html:326` loads `trains-db.js` with NO `?v=` query
```
<script src="trains-db.js"></script>
```
Once the SW caches this, it is pinned forever inside the current `ASSET_CACHE` generation. Every other page busts it with `?v=54.98-20260626cy`. g15 is now the odd-one-out and will diverge after any trains-db change until `CACHE_VERSION` rolls. Fix: append the same version string as g14-side.html.

### P1-2. Shared modules drift across the three pages
Same file, three versions:

| File | g14.html | g14-side.html | g15-pixi.html | g16-pixi.html |
|---|---|---|---|---|
| `obstacle-engine.js` | `cz` | `cy` | `cj` | `cj` |
| `kids-questions.js`  | `cz` | `cy` | `cj` | `cj` |
| `obstacles.js`       | `cz` | `cy` | `cj` | `cj` |
| `routes.js`          | `cz` | `cy` | `cj` | `cj` |
| `reward-catalog.js`  | `cz` | `cy` | `cj` | `cj` |
| `reward-gallery.js`  | `cz` | `cy` | `cj` | `cj` |
| `settings-modal.js`  | `cz` | `cy` | `cl` | `cl` |
| `rz-responsive.js`   | `20260422i` | (absent) | `20260423c` | `20260423c` |

Each `?v=` value becomes a distinct cache key, so the asset cache fan-outs and old generations linger until `CACHE_VERSION` purges. Worse, two pages can execute different revisions of the same module in the same session and trigger subtle behavioral mismatches. Land a single version-stamp pass after every shared-module ship.

## P2 — Observability / cleanup

- **P2-1.** No `console.info` on install/activate or precache success counts. Add one summary line per lifecycle event so the SW devtools waterfall has a signal.
- **P2-2.** Fetch handler logs nothing on cache-write failures (sw.js:114). Wrap `c.put` in `.catch(e => console.warn('sw cache.put failed', req.url, e))`.
- **P2-3.** No quota check. `caches.put` will silently fail on `QuotaExceededError`. Add a periodic prune (LRU on `ASSET_CACHE.keys()`) or at least surface the error.
- **P2-4.** `SW_UPDATED` reload uses `sessionStorage` guard keyed by version — survives one session only. Multiple rapid bumps in the same tab (this session: 12) will each fire one reload. Consider debouncing or coalescing.
