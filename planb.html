6 lapisan flat di atas digerakkan oleh RZParallax. Yang bikin "3D": tiap lapisan bergerak beda kecepatan + skala + blur + kabut sesuai kedalamannya.

01Konsep

Owner lihat messenger.abeto.co — game web yang terasa 3D. Itu WebGL/Three.js 3D beneran dengan gaya cel-shaded. Berat: butuh Blender/Houdini, bundle besar, rawan lag.

"buat engine parallax yang sangat2 keren… konsep dan masukkan mock up di planb."

Untuk game anak yang dibuka di HP/tablet, kita kejar kesan 3D-nya, bukan 3D-nya. Caranya: parallax berlapis. Tumpuk beberapa gambar 2D, gerakkan tiap lapisan dengan kecepatan berbeda menurut "jaraknya" dari kamera. Otak langsung membaca kedalaman. Ini trik yang dipakai Ori, Hollow Knight, dan game 2.5D papan atas — ringan, mulus, jalan di mana saja.

026 sinyal kedalaman yang dipakai engine

Parallax saja sudah meyakinkan. Tumpuk keenam sinyal ini dan otak benar-benar "melihat" ruang.

↔Parallax

Lapisan dekat bergerak jauh lebih cepat dari yang jauh. Sinyal kedalaman paling kuat.

⤢Skala

Objek dekat digambar lebih besar; yang jauh mengecil — perspektif.

≈Kabut udara

Yang jauh memudar ke warna langit (aerial perspective). Mendorong latar mundur.

◉Depth-of-field

Hanya bidang fokus yang tajam; depan & belakang sedikit blur — seperti lensa kamera.

◐Kontras

Latar jauh lebih datar/redup; subjek dekat lebih kontras dan hidup.

↑Gerak look-around

Geser mouse / miringkan HP → semua lapisan menyapu sesuai kedalaman. Ini "kamera 3D" semunya.

03Model lapisan (yang kamu lihat di mockup)

Tiap lapisan punya satu angka depth ∈ [0..1] (0 = tak terhingga jauh, 1 = tepat di kamera). Engine menurunkan semua transform dari angka itu.

LapisanDepthPeran
Langit + bulan + bintang0.00Gradien, nyaris diam. Latar paling jauh.
Pegunungan + kabut0.14Siluet berlapis, paling berkabut.
Bukit bergulir0.30Punggungan lembut, mulai bergerak.
Deret pohon / rumah0.46Detail menengah.
Rel + kereta FOKUS0.62Bidang tajam — subjek utama.
Semak depan (blur, cepat)1.00Menyapu di DEPAN kereta. Sinyal "dekat kamera" terkuat.

04API engine — games/parallax-engine.js

Inti engine cuma matematika — tak menyentuh DOM/canvas/Pixi. Instance yang sama menyetir mockup Canvas2D ini dan game Pixi. Satu sumber kebenaran.

// 1) buat sekali
const px = RZParallax.create({ strength: 30, autoScroll: 40 })
px.bindPointer(canvas)   // mouse + drag → lihat-sekeliling
px.bindTilt()           // gyro HP → lihat-sekeliling (izin iOS otomatis)

// 2) tiap frame (dt sudah di-clamp di dalam)
px.update(ticker.deltaTime)

// 3) tanya transform per lapisan
const t = px.layer(0.62)        // → { x, y, scale, blur, haze, dim }
sprite.x = baseX + t.x
sprite.y = baseY + t.y
sprite.scale.set(t.scale)
// blur/haze → filter di Canvas2D, atau alpha-overlay di Pixi

Karena murni angka, engine ini portabel ke semua game (kereta, Mario, Pokemon Run, bawah laut) — tiap game cuma mendaftarkan lapisannya.

NANTI

Blur halus depan/belakang, kabut mengikuti waktu-hari (pagi/sore/malam). Per-biome (salju, gurun, vulkanik).

NANTI

Sebar ke game lain

Mario Pokemon, Pokemon Run, Bawah Laut — masing-masing daftarkan lapisannya. Satu engine, banyak dunia.

06Kenapa tetap ngebut di tablet anak

≤ 6
lapisan per scene — bukan ratusan objek 3D
dt-clamp
tiap easing & scroll di-batasi min(dt, 3) — frame spike di tablet throttle tak meledak
0 aset
scene mockup digambar prosedural — tak ada model/tekstur 3D di-download
~300KB
tetap PixiJS 2D; bukan 5–10MB bundle WebGL 3D ala Three.js

Trade-off jujur: ini bukan 3D sungguhan (tak bisa muter kamera 360°). Tapi untuk side-scroller anak, kesan kedalaman + look-around sudah "sangat keren" dengan ongkos hampir nol. Kalau suatu hari mau 3D penuh → lihat plan.html (riset engine: tetap rekomendasi Pixi + sidecar).
